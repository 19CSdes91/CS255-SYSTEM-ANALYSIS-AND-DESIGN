# CS255-SYSTEM-ANALYSIS-AND-DESIGN
Reflection:
Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design? 

The DriverPass project was about designing a system for a driving education company. The client, Liam and his IT lead, wanted to create a site where students could prepare for their DMV tests. Some of the features included scheduling lessons, taking practice tests, and tracking progress. 

What did you do particularly well? 

Something I did well was turning the client’s needs into a clear system model using multiple diagrams such as Gantt, activity, sequence, and class diagrams. 

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it? 

If I could go back and revise my work, I would add more detail to some of my diagrams to better capture the client’s needs. 

 

How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing? 

When designing the system, I focused on simplicity. I wanted it to be easy for users to navigate so they could quickly schedule lessons or take practice exams after logging in. This is important because the system is made for the user, and if it is too difficult to use, they may not want to use it. 

How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system? 

When designing software, I have learned to make a plan before jumping in by focusing on organization and clarity. In the future, I will continue using diagrams, thinking about the users who will interact with the system, and considering how the system will function as a whole, including security and functionality.
